mysbx - my sandboxing tool

Usage:
  mysbx [--dry-run] [--verbose] [--multiplexer <mux>] [--backend <name>] [--session <name>] [--ro <path>]... [--rw <path>]...
  mysbx run [--dry-run] [--verbose] [--result] [--timeout <seconds>] [--backend <name>] [--session <name>] [--ro <path>]... [--rw <path>]... -- COMMAND...
  mysbx gui [ARG...]
  mysbx fetch | merge | push | diff NAME [verb-arguments...]
  mysbx session list | session destroy NAME [--force] | session hunk NAME
  mysbx worktree list | worktree diff NAME | worktree hunk NAME
  mysbx status
  mysbx ssh-pubkey
  mysbx [COMMAND]

Commands:
  (none)        enter an interactive sandbox shell for the current repo;
                the repo must have been initialized with `mysbx init`
                first — a run creates nothing;
                with `multiplexer = "tmux"|"workmux"|"herdr"|"aoe"|"orca"` in
                a config layer this is a session of that multiplexer
                instead of a bare shell, on a socket inside the sandbox
  run -- CMD... run one command in the sandbox; everything after `--` is
                passed to the command verbatim; needs `mysbx init` too.
                With `--result` the run does not exec the payload: it
                waits for it, writes its outcome to
                `<repo>.mysbx/result.json` and exits by the interpreted
                contract (`0` completed, `1` failed, `124` timed out,
                `130`/`143` cancelled, `70` infrastructure error) —
                `--timeout <seconds>` bounds it; without `--result`
                the payload's own exit code propagates unchanged and
                no result file is written
  gui [ARG...]  open an alacritty terminal in the current directory
                and run `mysbx ARG...` in it; everything after the
                verb is passed to that inner mysbx verbatim — so
                `mysbx gui --multiplexer herdr` starts the session in
                a window. No sandbox is started by `gui` itself: the
                inner invocation is the run and reports its own
                errors in the window. This form needs a graphical
                session (Wayland/X11) and returns as soon as the window
                opens — detached like `mysbx gui & disown`, so the shell
                prompt comes back immediately and the window survives
                the terminal it was typed in
  init          create the sidecar directory next to the current repo;
                the only command that initializes a repo; idempotent:
                an existing config.toml is never rewritten
  init --approve-git-dirs
                additionally approve the git metadata directories the
                repo still needs in an EXISTING config.toml — the
                recovery for a config created without approvals (by
                `mysbx edit`, by hand, or before the checkout became a
                linked worktree); adds only missing entries
  edit          open the sidecar config.toml of the current repo in
                $EDITOR (or $VISUAL); creates it first when missing,
                like `init` would. The host-wide user config is
                not what this edits
  fetch NAME    bring the session branch agent/mysbx/NAME of the
                named session into the host repo — a fast-forward-only
                fetch of the session's clone, fully qualified on both
                sides, no tags: an absent host-local branch is
                created, an ancestor is advanced, a diverged or
                rewound one is REJECTED without being touched
                (rebased session history stays an explicit operator
                action). The host repo learns nothing permanent
                about the clone: no remote is configured. No sandbox
                is started; the repo is the one the current directory
                resolves to. With --dry-run the exact git commands
                are printed instead
  merge NAME [--no-ff|--ff|--squash] [-- GIT-MERGE-ARGS...]
                merge the fetched session branch into the currently
                checked-out branch of the host repo. Refuses a
                detached HEAD and a dirty host tree first; --no-ff is
                the default, --ff/--squash/explicit git-merge args
                pass through. After the fetch the merge consumes the
                EXACT ref refs/heads/agent/mysbx/NAME — never the
                bare name a same-named tag could shadow — and on
                success the fetched host-local ref is deleted again
                (it was the ferry copy); on conflict it stays, with
                the recovery hint. No sandbox is started
  push NAME [REMOTE]
                publish the session branch: the implicit fetch
                first (the pushed ref is current), then
                `git push REMOTE refs/heads/…:refs/heads/…` through
                the HOST REPO's own remotes — REMOTE defaults to its
                `origin`. Explicit, non-forced, fully qualified.
                git's own exit code and diagnostics pass through
  diff NAME     the changes on the session branch since it diverged
                from the host's HEAD: the implicit fetch, then the
                THREE-DOT diff `git diff
                HEAD...refs/heads/agent/mysbx/NAME` — not the host's
                own drift. git's own exit code and diagnostics pass
                through
  session list  the sessions of the current repo, one line per
                `clones/` entry — the directory is the registry —
                with the name, the session branch
                `agent/mysbx/NAME`, and the ahead-count (the commits
                in the session branch that the host repo does not
                have; `-` when no honest number can be computed). An
                entry without `.git` is debris of an interrupted
                creation and is marked as such. Starts no sandbox;
                with --dry-run the exact git probe commands are
                printed instead
  session destroy NAME [--force]
                remove the named session's clone — a guarded removal
                (intrinsic properties, not location trust): the
                resolved path must be strictly inside
                `<repo>.mysbx/clones/`, its basename must equal NAME,
                never the sidecar root, never `/`. REFUSES while the
                session branch holds commits the host repo does not
                have (unmerged work) unless --force is given — the
                refusal names the branch and the merge to run
                instead. The clone is plain `rm -rf`'d (it is
                standalone, no worktree bookkeeping), the per-session
                result file `clones/NAME.json` goes with it, the
                host repo is untouched and a host-local
                `agent/mysbx/NAME` branch left by a fetch is kept —
                it is the operator's imported copy. With --dry-run
                the exact probe and removal commands are printed
                instead, and nothing is removed
  session hunk NAME
                the session's diff — the same range `mysbx diff NAME`
                shows — in the interactive `hunk` viewer: the implicit
                fast-forward fetch of the session branch into the host
                repo, then `hunk diff
                HEAD...refs/heads/agent/mysbx/NAME` exec'd with the
                host repo as the working directory — the tool owns
                the terminal and its exit code propagates unchanged,
                like `$EDITOR` does for `mysbx edit`. Refuses a session
                without a `.git` (debris). With --dry-run the exact
                fetch and `hunk` commands are printed instead
  worktree list the host's workmux worktrees — the directories of the
                `<repo>__worktrees` sibling — one line per entry with
                the handle, the checked-out branch, and the
                ahead-count (the commits in the worktree's branch that
                the base branch does not have; `-` when no honest
                number can be computed). An entry without a `.git`
                pointer is debris and is marked as such. Starts no
                sandbox; with --dry-run the exact git probe commands
                are printed instead
  worktree diff NAME
                the changes on the named worktree's branch since it
                diverged from its BASE branch: the THREE-DOT diff
                `git -C <worktree> diff <base>...<branch>`. The base
                is workmux's own record —
                `branch.<branch>.workmux-base` of the host repo's
                config — falling back to `master`, then `main`, then
                the host repo's HEAD when no record exists; the base
                that answered is reported to stderr. git's own exit
                code and diagnostics pass through
  worktree hunk NAME
                the same three-dot range in the interactive `hunk`
                diff viewer, exec'd with the worktree as the working
                directory — the tool owns the terminal and its exit
                code propagates unchanged, like `$EDITOR` does for
                `mysbx edit`. With --dry-run the exact `hunk`
                invocation is printed instead
  status        the one-command overview of this repo's mysbx setup,
                host-side (no sandbox is started): the resolved repo
                and sidecar with the init state (inited, or `not
                inited` with the `mysbx init` hint), the effective
                configuration a run would use — the backend (with
                the layer that contributed it; when the sidecar is
                not inited, from the user layer alone, with the
                run-refusal named), the multiplexer, the network
                sense — and the session and worktree registries in
                the SAME one-line format `session list` and
                `worktree list` print (or a short `none` line each).
                Exit 0 even on a not-inited repo: status reports the
                state, it never judges it. Takes no nested verbs;
                --verbose is refused (no run to report on) and
                --dry-run is accepted as a plain print (the verb has
                no side effects)
  ssh-pubkey   print the PUBLIC half of this repo's sandbox ssh
                keypair (<repo>.mysbx/state/.ssh/id_ed25519.pub) —
                the value to register as a GitHub deploy key or a
                gitolite keydir entry; the private key never leaves
                the sidecar/sandbox. Host-side, no sandbox is
                started. The keypair is always generated (the verb
                enforces the run lifecycle: a
                missing pair is generated, an incomplete one
                repaired, an existing one left untouched).
                Takes no nested verbs;
                --verbose is refused and --dry-run prints what
                would happen without generating anything
  gvisor-load-image
                load the gVisor agent container image into Podman;
                supports `--force`, `--test`, `--image <ref>`, `--help`
  version       print the version
  help          print this help

Options:
  --dry-run     print the exact bwrap invocation — the executable
                (argv[0]) first, then the sandbox argv, one argument
                per line — and exit; must precede the command, creates
                nothing and runs no command. An uninitialized repo is
                refused here too: the sidecar is part of the run it
                would print. With `--session`, the git commands of the
                clone creation are printed in the same format before
                the argv when this is the session's first run. With the
                handoff verbs (fetch/merge/push/diff), the exact git
                commands of the handoff are printed in the same format
                instead of run; with the session verbs (session list,
                session destroy, session hunk) the exact probe and
                removal commands are printed the same way; with the
                worktree verbs (worktree list, worktree diff, worktree
                hunk) the exact probe and diff commands are printed the
                same way
  --verbose     print the run configuration (repo, config files, backend,
                network, mounts, environment, payload) to stdout with a
                `## ` prefix before running; must precede the command.
                Note: [env] values are printed verbatim and may be secrets
  --multiplexer <mux>
                the multiplexer of THIS interactive run, overriding the
                `multiplexer` of the config layers for one invocation —
                the next run uses the configuration again. <mux> is one
                of: tmux, workmux, herdr, aoe, orca, none (the same closed set
                as the config key); `none` forces the plain shell. Bare
                form only: a `run -- CMD` never starts a session, and
                every other verb rejects the flag. A value this build
                pinned no entry for is a refused run, like a config
                layer selecting it
  --backend <name>
                the sandbox backend of THIS run, overriding the
                `backend` of the config layers for one invocation —
                the next run uses the configuration again. <name> is
                one of: bubblewrap, podman-gvisor, nono (the same accepted
                set the pipeline enforces on the configuration);
                anything else is a refused run (exit 70) naming the
                set, never a silent fallback — and neither layer has
                to name a backend for the flag to select one. Valid
                before the verb and after it for `run`; every other
                verb rejects it
  --session <name>
                run in the named session's clone (the clone mode of
                docs/design/workspace.md): the session's standalone
                git repository `<repo>.mysbx/clones/NAME` is bound
                rw at the repo's own path, the host repo itself is
                not mounted at all, every configured mount is forced
                read-only and `--rw` is refused — the clone is the
                only writable bind. The FIRST `--session NAME` run
                creates the clone from the host repo's current HEAD
                on the session branch `agent/mysbx/NAME`
                (continuing at an existing tip when an earlier
                session left the branch in the host repo); an empty
                host repo and a host branch named `agent` are
                refused. <name> matches [A-Za-z0-9][A-Za-z0-9._-]{0,63}
                — no slashes, no leading dot; anything else is a
                usage error. With `run --result` the outcome is
                written to `<repo>.mysbx/clones/NAME.json` instead
                of result.json. Valid before the verb and after it
                for `run`; every other verb rejects it. There is no
                configuration for sessions: the flag is the whole
                switch, and `clones/` is the registry
  --ro <path>   bind one more host file or directory into the sandbox
                of THIS run, read-only — on top of every `[[mounts]]`
                entry of the config layers, in addition to them, never
                replacing anything. <path> is a host path in the same
                three forms a `[[mounts]]` path accepts (absolute,
                `~/…` expanded against $HOME, or relative to the
                current directory) and must exist. Repeatable: one
                bind per value, every --ro before every --rw (so --rw
                wins a same-path tie no matter the typing order), the
                values of each flag in the order given. Valid before the
                verb and after it for `run`; every other verb rejects
                it. A path that is — or contains — the host home is
                refused, exactly like a config entry naming it. The
                next run uses the configuration again
  --rw <path>   the same, read-write: the payload may write the host
                path through the bind. The next run uses the
                configuration again — for a persistent grant, put a
                `[[mounts]]` entry in the sidecar config (`mysbx edit`)
  --result      with `run -- CMD`: wait for the payload and record its
                outcome in `<repo>.mysbx/result.json` (state, exit
                code, payload exit code or signal, timestamps, the
                timeout budget) instead of exec'ing it — the exit code
                is mysbx's interpreted one, the payload's stdout is
                untouched and the file's path is printed to stderr.
                Valid before the verb and after it for `run`; every
                other invocation rejects it — an interactive shell has
                no consumable outcome
  --timeout <seconds>
                the budget of a `--result` run: when the payload
                outlives it, the whole sandbox process group is
                killed and the run is recorded as `timed-out`, exiting
                `124`. Requires `--result` — a plain run ends in an
                exec, and no budget can apply to a process that is
                no longer mysbx. A positive whole number of seconds
  -h, --help    print this help
  -V, --version print the version

Exit codes (cli.md D8):
  0             success — the payload exited 0 (a `--result` run:
                state `completed`)
  1             the payload failed — its own non-zero exit code under
                the exec passthrough, or the `failed` state of a
                `--result` run (a payload killed by a signal records
                the signal in the result file)
  2             usage error — the command line is wrong
  70            infrastructure error — mysbx's own runtime failure:
                the command line was fine but the run it named could
                not happen (no sidecar, unparsable config, no backend,
                the backend could not be started). `70`, not `1`, so a
                payload's own `1` can never be mistaken for the
                tool's failure
  124           a `--result` run exhausted its `--timeout` budget
  130 / 143     a `--result` run was cancelled — SIGINT / SIGTERM
                arrived while mysbx waited; the sandbox was killed and
                the state is `cancelled` (the shell's 128 + signum)
