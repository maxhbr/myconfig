mysbx - my sandboxing tool

Usage:
  mysbx [--dry-run] [--verbose] [--multiplexer <mux>] [--ro <path>]... [--rw <path>]...
  mysbx run [--dry-run] [--verbose] [--ro <path>]... [--rw <path>]... -- COMMAND...
  mysbx gui [ARG...]
  mysbx [COMMAND]

Commands:
  (none)        enter an interactive sandbox shell for the current repo;
                the repo must have been initialized with `mysbx init`
                first — a run creates nothing;
                with `multiplexer = "tmux"|"workmux"|"herdr"|"aoe"` in
                a config layer this is a session of that multiplexer
                instead of a bare shell, on a socket inside the sandbox
  run -- CMD... run one command in the sandbox; everything after `--` is
                passed to the command verbatim; needs `mysbx init` too
  gui [ARG...]  open an alacritty terminal in the current directory
                and run `mysbx ARG...` in it; everything after the
                verb is passed to that inner mysbx verbatim — so
                `mysbx gui --multiplexer herdr` starts the session in
                a window. No sandbox is started by `gui` itself: the
                inner invocation is the run and reports its own
                errors in the window. This form needs a graphical
                session (Wayland/X11) and returns as soon as the window
                opens — detached like `mysbx gui & disown`, so the shell
                prompt comes back immediately and the window survives
                the terminal it was typed in
  init          create the sidecar directory next to the current repo;
                the only command that initializes a repo; idempotent:
                an existing config.toml is never rewritten
  init --approve-git-dirs
                additionally approve the git metadata directories the
                repo still needs in an EXISTING config.toml — the
                recovery for a config created without approvals (by
                `mysbx edit`, by hand, or before the checkout became a
                linked worktree); adds only missing entries
  edit          open the sidecar config.toml of the current repo in
                $EDITOR (or $VISUAL); creates it first when missing,
                like `init` would. The host-wide user config is
                not what this edits
  version       print the version
  help          print this help

Options:
  --dry-run     print the exact bwrap invocation — the executable
                (argv[0]) first, then the sandbox argv, one argument
                per line — and exit; must precede the command, creates
                nothing and runs no command. An uninitialized repo is
                refused here too: the sidecar is part of the run it
                would print
  --verbose     print the run configuration (repo, config files, backend,
                network, mounts, environment, payload) to stdout with a
                `## ` prefix before running; must precede the command.
                Note: [env] values are printed verbatim and may be secrets
  --multiplexer <mux>
                the multiplexer of THIS interactive run, overriding the
                `multiplexer` of the config layers for one invocation —
                the next run uses the configuration again. <mux> is one
                of: tmux, workmux, herdr, aoe, none (the same closed set
                as the config key); `none` forces the plain shell. Bare
                form only: a `run -- CMD` never starts a session, and
                every other verb rejects the flag. A value this build
                pinned no entry for is a refused run, like a config
                layer selecting it
  --ro <path>   bind one more host file or directory into the sandbox
                of THIS run, read-only — on top of every `[[mounts]]`
                entry of the config layers, in addition to them, never
                replacing anything. <path> is a host path in the same
                three forms a `[[mounts]]` path accepts (absolute,
                `~/…` expanded against $HOME, or relative to the
                current directory) and must exist. Repeatable: one
                bind per value, every --ro before every --rw (so --rw
                wins a same-path tie no matter the typing order), the
                values of each flag in the order given. Valid before the
                verb and after it for `run`; every other verb rejects
                it. A path that is — or contains — the host home is
                refused, exactly like a config entry naming it. The
                next run uses the configuration again
  --rw <path>   the same, read-write: the payload may write the host
                path through the bind. The next run uses the
                configuration again — for a persistent grant, put a
                `[[mounts]]` entry in the sidecar config (`mysbx edit`)
  -h, --help    print this help
  -V, --version print the version
